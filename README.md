# 卓編數位書房 (Digital Editor Zhuo) V11.0

艾維斯資訊顧問 IT ‧ Elvis 程式設計

法鼓山榮譽董事會 AI 編輯代理人，將活動報導潤稿、人物專訪提煉、活動 DM 文案撰寫標準化，並用「大神的便條紙」規則庫確保全組文宣品質一致。

## 這是兩個獨立專案

```
卓編數位書房-V2/
├── frontend-project/      # 前端靜態站（部署到 GitHub Pages）
│   ├── index.html
│   ├── app.js
│   ├── logo.png
│   └── README.md           ← 前端部署說明
│
└── worker-project/         # Cloudflare Worker（AI 代理 + 規則庫 KV）
    ├── src/index.js
    ├── wrangler.toml
    ├── package.json
    ├── .gitignore
    ├── .dev.vars.example
    └── README.md            ← Worker 部署說明（wrangler CLI）
```

兩者各自是完整、可獨立進版控的專案（各自的 `README.md` 有完整部署步驟），中間只靠一個網址銜接：

```
frontend-project/app.js 裡的 WORKER_BASE_URL
        ↓ 必須等於
worker-project 部署後拿到的正式網址
```

## 建議部署順序

1. **先部署 `worker-project/`**（見該資料夾 README，`wrangler deploy` 即可），拿到正式網址
2. 把網址填入 `frontend-project/app.js` 的 `WORKER_BASE_URL`
3. **再部署 `frontend-project/`** 到 GitHub Pages（見該資料夾 README）

## 為什麼要拆成兩個專案、中間夾一個 Worker？

GitHub Pages 是純靜態站，任何人可檢視原始碼；如果 Gemini API Key 直接寫在前端，等於公開給所有人。`worker-project` 的存在就是把 Key 藏在 Cloudflare 後端（Secrets），前端只呼叫自己的 Worker 網址，並內建三組備援 Key 自動 failover（額度用盡自動切換下一組）。便條紙規則庫也一併放在 Worker 的 KV 儲存，讀寫都不需曝光任何憑證。

## 核心功能

| 功能 | 說明 |
|---|---|
| 潤稿中心 - 活動報導 | 梳理人事時地物、去贅字、自動加小標題 |
| 潤稿中心 - 人物專訪 | 萃取學佛因緣／護法願心，產出 3 個禪意備選標題 |
| 文案中心 - 活動 DM | 起承轉合架構，自動生成宣傳文案 |
| 大神的便條紙 | 規則庫管理，其餘三功能即時套用啟用中的規則 |

### V11（2026-08-02）

修正改用 Cloudflare Pages 公開部署後 API 連不上的問題。僅調整 `worker-project/`（前端 `frontend-project/` 僅同步更新版本號，邏輯未變動）：

- **問題背景**：前端原本部署在 GitHub Pages（`https://elvis2026-maker.github.io`），Worker 的 `ALLOWED_ORIGINS` 白名單只放了這一個網域。改用 Cloudflare Pages 對外公開（`https://peng-8xl.pages.dev`）後，瀏覽器帶著新的 Origin 呼叫 Worker，會被 CORS 檔在瀏覽器端擋下（Console 會看到 `CORS policy` 相關錯誤），前端會誤以為是「API 連不上」，但其實 Gemini Key 與 KV 都正常，單純是這個 Worker 沒有放行新網域。
- **修正 `ALLOWED_ORIGINS`**：改為陣列同時放行兩個網域，GitHub Pages 與 Cloudflare Pages 雙邊都能正常呼叫同一個 Worker，未來若其中一邊網址變動，直接在這個陣列增減即可：
  ```js
  const ALLOWED_ORIGINS = [
    "https://elvis2026-maker.github.io",
    "https://peng-8xl.pages.dev",
  ];
  ```
- **⚠️ 重要：改完程式碼後必須重新 `wrangler deploy`**，Worker 的程式碼修改不會自動生效，需要重新部署到 Cloudflare 才會套用新的 CORS 白名單。
- **前端 `WORKER_BASE_URL` 不需要變動**：`frontend-project/app.js` 裡的 `WORKER_BASE_URL` 呼叫的是 Worker 網址（`https://elvis-peng.elvis-liu2027.workers.dev`），跟你放前端的 Pages 網址是兩件事，不用改。
- **若之後想把 Worker 也綁到自訂網域**，或前端網址又換了，記得同步回來這個 `ALLOWED_ORIGINS` 陣列補上新網址，否則會重演同樣的 CORS 問題。

### V08（2026-07-30）

視覺沉浸感升級：審稿動畫更炫彩、頁面切換加入過場、四大卡片圖示改為全彩立體風格。僅調整 `frontend-project/`（`worker-project/` 未變動，無需重新部署）：

**審稿中動畫（「大神親自潤稿」沉浸感）**

- **柔光暈呼吸**：原本三圈墨暈背後新增一圈金色柔光（SVG `radialGradient`），隨 2.6 秒週期緩緩放大縮小、忽明忽暗，象徵「有大神在場」的靈氣感，而非單純的等待圖示。
- **墨暈改為色相流動**：三圈暈染圓環從單一綠色改為金→綠→棕漸層（`linearGradient`），並疊加 `hue-rotate` 讓色彩持續緩慢流動，暈開時色澤會微微變化，而不是死板的單色圈圈。
- **毛筆真的在「寫字」**：筆觸路徑旁新增一顆沿同一條路徑移動的金色光點（`offset-path`），配合原本畫出筆觸的動畫同步進行，看起來像是筆尖正在落墨書寫，而非單純畫一條線然後消失；筆觸本身也疊加一層模糊金色高光，讓線條更有墨韻立體感。
- **環繞金粉粒子**：新增三顆微小金色圓點，錯開時間緩緩上浮、淡出，呼應「有靈氣圍繞」的意象。
- **文字流光**：載入文字（如「卓編正在提筆潤稿」）改為棕綠金三色漸層並持續向右流動（`background-clip: text` + `background-position` 動畫），取代原本純灰階文字。
- **效能與無障礙**：全部純 CSS + SVG（含 `<defs>` 漸層），不引入額外套件或圖片；`prefers-reduced-motion` 使用者會停用所有新增動畫，僅保留靜態圖形與原有文字色彩，不受影響。四個功能頁（活動報導／人物專訪／活動 DM／潤稿前後對照批次）共用同一組 `INK_LOADER`，因此四處的審稿動畫已同步升級。

**頁面切換過場動畫**

- 原本點擊頂部選單或卡片切換頁面是瞬間跳轉；現在改為「淡出上移舊頁面（0.14 秒）→ 淡入上移新頁面（0.42 秒）」的兩段式過場，視覺上更接近翻頁的感覺。純 CSS `@keyframes` 實作，`showPage()` 邏輯拆出 `renderTargetPage()` 輔助函式以搭配過場計時器；`prefers-reduced-motion` 使用者會直接跳過過場，維持原本的瞬間切換，不受影響。

**四大卡片圖示：全彩立體水墨浮雕風格**

- 首頁四張卡片（活動報導／人物專訪／活動 DM／大神的便條紙）的圖示，從 V3 開始的純白線條圖示，全面升級為多層次全彩漸層圖示：
  - **活動報導**：稿紙改為暖白到米褐的紙面漸層，並加上底部陰影與摺角光澤，右上角潤飾筆觸改為金棕漸層。
  - **人物專訪**：兩位對談者剪影分別採用膚色系（前）與淡綠色系（後）漸層，並加上細緻高光線條，呈現更立體的人物層次。

### V07（2026-07-30）

手機版介面調整、視覺優化，以及五項功能擴充，僅調整 `frontend-project/`（`worker-project/` 未變動，無需重新部署）：

**介面調整**

- **修正手機版頂部選單需要橫向滑動的問題**：原本 5 個選單項目（首頁／活動報導／人物專訪／活動 DM／大神的便條紙）在窄螢幕會超出可視範圍，需要左右滑動才能看到全部；現在改為 5 個項目平均分配寬度、一次全部呈現在同一行，不需滑動即可看到並點擊任何一個。文字統一不換行（`white-space: nowrap`），並隨螢幕寬度分兩段微調：760px 以下先縮小字級與間距、隱藏副標題「DIGITAL EDITOR ZHUO」；400px 以下（較舊的小尺寸手機）進一步隱藏選單圖示、只留文字，確保五個字的項目名稱（如「大神的便條紙」）都能完整顯示不被截斷或擠壓變形。
- **「知識庫已連線」文字膠囊改為單純燈號**：原本常駐顯示的文字膠囊會佔用不少版面、手機上更明顯，現在改為一顆直徑 30px 的圓形燈號，用顏色辨識狀態即可：綠色＝知識庫已連線、紅色＝連線異常、灰色＝示範模式（尚未串接 Worker），並帶有輕微脈動動畫提示「這是即時狀態」（已對 `prefers-reduced-motion` 使用者停用動畫）。完整文字說明移到滑鼠 hover 時顯示的提示（桌機），手機則改為點一下燈號會彈出文字小泡泡、2 秒後自動收起，不需要一直佔用畫面空間。

**五項功能擴充**

- **便條紙篩選＋建立日期顯示**：「大神的便條紙」清單上方新增「全部／本週新增／僅看自動歸納」三個篩選按鈕，並在每則規則卡片顯示建立日期（如「7/28 新增」），方便定期檢查最近自動歸納出來的內容是否合理。篩選是純前端運算，不影響 Worker 端資料。
- **規則庫一鍵匯出備份**：篩選列旁新增「備份 JSON」與「備份 Word」兩個按鈕。JSON 備份完整保留所有欄位（含 id、is_active、created_at），可作為日後還原或匯入其他系統的原始資料；Word 備份則依分類分段列出規則文字與建立日期，適合列印或傳閱給其他編輯參考。KV 儲存本身沒有版本記錄，這兩個備份按鈕可作為誤刪之後的復原依據（目前僅支援匯出，尚未支援從備份檔一鍵匯入回寫，如需還原請手動用「新增叮嚀」逐條輸入或直接在 Cloudflare 後台操作 KV）。
- **潤稿前後併排比對（Diff 顯示）**：活動報導、人物專訪兩項功能的潤稿結果區塊，新增「顯示修改處對照」按鈕，按下後會用逐字比對（LCS 演算法）標示卓編實際改動了哪些字——綠底底線代表新增／修改後的內容，紅底刪除線代表被移除的原文，方便判斷潤稿品質、或決定要不要把某個修改習慣手動加進便條紙規則庫。此功能完全在瀏覽器端運算，不會呼叫 Worker；若原文或潤稿結果任一邊超過 6000 字，為避免瀏覽器計算卡頓，會改為提示「篇幅較長暫不提供逐字對照」。活動 DM 撰寫功能沒有這個按鈕，因為 DM 是從零生成文案、沒有「潤稿前」原文可供比對。
- **草稿自動保存**：活動報導、人物專訪、活動 DM 三項功能的輸入欄位（初稿、活動資訊等，不含卓編潤稿後的結果）會自動存進瀏覽器的 `localStorage`（每次輸入後 debounce 0.8 秒寫入一次）。若使用者寫到一半被通知打斷、不小心切出頁面或重新整理，回到該功能頁時會看到一條「偵測到 X 月 X 日 X 時 X 分未送出的草稿，是否還原？」提示條，可選擇還原或清除；成功送出潤稿／文案後會自動清除當次草稿暫存。此功能純前端運作，不會把草稿內容送到 Worker 或任何伺服器；若瀏覽器為無痕模式或儲存空間已滿導致 localStorage 寫入失敗，會靜默略過、不影響主要送出功能。
- **批次處理（潤稿前後對照）**：「大神的便條紙」頁面的「潤稿前後對照 → 自動歸納規則」區塊下方，新增「批次佇列」子區塊。使用者可以像原本一樣填好一組「潤稿前／潤稿後」（含 Word 檔匯入），但改按「加入批次佇列」而非直接送出分析，即可把這一組暫存進佇列並清空輸入框繼續填下一組；累積多組之後，按「開始批次分析」會依序（非並行，避免同時打爆三組備援 Key 額度）逐篇呼叫卓編分析，完成後彙總顯示每一篇個別找到／新增／略過的規則數量，並統一顯示總計。原本「分析並歸納規則」單篇即時分析的按鈕與行為完全保留，未受影響，佇列功能是額外新增的選項，需要處理多篇文章時才使用；批次分析全部處理完後會自動清空佇列，避免不小心重複分析同一批。

- **自動略過重複規則**：每次分析前會先比對目前便條紙裡「內容完全相同」的規則，重複的會自動略過、不重複新增，分析完成後會顯示「新增幾條、略過幾條重複」的摘要。請注意這裡的比對是「文字完全一樣」才算重複，如果卓編兩次分析出來的規則文字略有出入（即使意思相同），仍會被視為不同規則而新增，需要的話可自行到清單裡刪除多餘的。
- **一次僅支援一組前後對照**：目前設計是一次分析一篇文章的潤稿前後版本；若要處理多篇，需要逐篇重複操作。
